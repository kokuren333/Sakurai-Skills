# Write specifications for implementation and review

## Summary
Describe observable behavior, parameters, ownership, and edge cases for relevant disciplines.

## SOURCE
Specification material advocates compact, concrete, implementation-facing descriptions. This is a thematic attribution to supplied intermediate material, not a verified quotation or timestamp. See [preserved source](../sources/raw/D-specification.md).

## GENERALIZED
Tie requirements to player-visible behavior and testable evidence.

## AGENT
Avoid over-specifying exploratory questions before evidence exists.

## Apply when
- Project scope includes this decision and context supports the intended outcome.

## Questions
- What player-visible outcome is at stake?
- What evidence supports this diagnosis?
- Which constraints or countervailing principles matter?

## Review criteria
- Tie advice to evidence or explicit assumptions.
- State tradeoffs, exceptions, and a small validation step.
