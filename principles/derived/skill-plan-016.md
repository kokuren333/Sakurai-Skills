# 続編開発におけるシステム基盤継承と上乗せ投資の原則

## Summary
続編は前作のシステム資産を流用してリードを稼ぎつつ、単なる同規模にとどまらず前作を凌駕する魅力を注ぎ込め。

## GENERALIZED
「アーキテクチャ再利用によるコンテンツ密度への再投資」。新規開発の初期コスト（エンジン選定・ツール制作・基本挙動）をスキップできる続編の利点を生かし、その余剰リソースを独自の追加価値・新メカニクスへと全投入する。

## AGENT
『スマブラfor』から『スマブラSP』への移行は開発元（バンダイナムコスタジオ）が同じであったため基盤を継承でき、全ファイター参戦という破格のスケールを実現できた好例。

## Why it matters
前作と同じ規模・同じ手触りの続編は「前作で体験済み」と判定され、プレイヤーの購入意欲が半減するため。

## Agent questions
- 前作のコードベースやツールから再利用可能なコンポーネントが明確に切り出されているか？
- 前作を遊び尽くしたプレイヤーが「買い直す価値がある」と一目でわかる新機軸が提示されているか？

## Suggested actions
- 前作のエンジン・ツール群の負債を解消しつつ、新機能開発にリソースを集中させる計画を立てる。
- 「前作の不満点解消」＋「前作にはなかった全く新しいコア体験」をセットで企画する。

## Anti-patterns
- 続編だからといってシステムをゼロからフルスクラッチし、前作よりコンテンツ量が減ってしまう現象。
- システムは流用したが中身が前作のマップ差し替え程度で、新鮮味が皆無な設計。
