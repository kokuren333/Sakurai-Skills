## AGENT

## Why it matters
身体的特性、持ち方、慣れ親しんだ他作品の操作感など、プレイヤーの入力環境は多様であり、固定操作はプレイ断念の直接原因となる。

## Use with context
- Domains: Input System, UI/UX, Accessibility
- Phases: System Architecture, UI Implementation
- Trigger: キーコンフィグ機能、入力マッピング管理モジュールの設計・コード生成時

## Agent questions
- 入力リマップ画面で入力待ち受け状態が明確に分離されているか？
- 必須機能（決定・ポーズ・移動等）の未割り当てチェックが実装されているか？

## Suggested actions
- リマップ用モーダルダイアログを実装し、一定秒数無入力または特定キャンセルキーで中断できる安全機構を組む。
- 割り当て変更時にUIプロンプトアイコンの動的再生成イベントを発火させる。

## Review criteria
- すべての操作可能アクションが任意キーに再設定可能であること。
- 操作設定がローカルプロファイルに永続化され、次回起動時も維持されること。

## Anti-patterns
- 項目を選んだ瞬間にキー入力を受け付けるモードになり、キャンセルしようとBボタンやEscを押すとそれがそのままバインドされてしまう罠。
- ハードウェア標準のリマップ機能があるからという理由でインゲームのキーコンフィグを省くこと。

## Tradeoffs and exceptions
- Tradeoff: 全アクションの自由なリマップを許可すると、コンボ入力や同時押し判定の破綻リスクが増えるため、排他制御や警告バリデーションが必要になる。
- Exception: ワンボタン完結型のミニゲームや、システム根幹の操作（PSボタン、HOMEボタン等）。
