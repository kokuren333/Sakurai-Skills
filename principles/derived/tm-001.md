# 日報と『きょうの一枚』による日常的・視覚的な情報共有

## Summary
開発進捗や考察を日報に記録し、開発中の最新スクリーンショットを1日1枚共有してチームの視覚的同期を図る。

## SOURCE
大型ゲームでは各自が何を作っているか見失いがちになる。日報ページを設け、開発進捗・出来事・考えを3〜5トピック程度記載するとともに、開発中のスクリーンショット（きょうの一枚）を毎日1枚掲載する。スタッフがコメント欄でリアクションできるようにする。

## GENERALIZED
テキストベースの進捗報告に加えて、視覚的アーティファクト（最新ビルドのキャプチャやGIF）を日次で共有することで、分業による全体像の喪失を防ぎ、心理的安全性の高いコミュニケーションハブを形成する。

## AGENT
CI/CDや自動ビルドパイプラインと連携し、毎日のデイリービルドから自動または手動でゲーム画面のスナップショットを投稿するボット/チャンネルを運用するとエージェント運用と相性が良い。

## Why it matters
全体像や目的が見えない作業はメンバーのストレスになり、モチベーション低下や仕様の乖離を引き起こす。また、メール等の全体周知は読まれないが、画像付きの日報は自発的な閲覧と刺激・気づきを生む。

## Use with context
- Domains: Team Communication, Project Management, Culture
- Phases: Pre-production, Production, Alpha, Beta
- Trigger: デイリータスク終了時、またはプルリクエスト/ビルド生成時

## Agent questions
- 本日コミットされたビジュアルまたは機能の変更点が画像/動画で可視化されているか？
- 変更の意図や懸念点が他職種にも平易な言葉で言語化されているか？

## Suggested actions
- 最新ビルドの動作確認画面からスクリーンショットを1枚キャプチャして進捗サマリに添付する。
- 変更点・発生した課題・所感を3行程度に要約したデイリーログを生成する。

## Review criteria
- 視覚的アーティファクトが添付されていること。
- 専門用語を多用せず、他職種（アート/サウンド/企画）でも理解可能な表現であること。

## Anti-patterns
- テキストのみの長文メールで全体進捗を送信し、誰も読まない状態を放置する。
- 完成間際まで他セクションの成果物が動いている様子を非公開にする。
