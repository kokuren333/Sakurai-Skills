# シリーズ集大成の断行と持続可能なパラメータ資産パイプラインの構築

## Summary
『全員参戦』のような不可能に見える集大成を実現するためには、前作の制作資産・開発環境を継承し、パラメータ調整をチームへ委譲せよ。

## GENERALIZED
極限規模のコンテンツ量（全員参戦）を達成するための唯一の解は、前作のエンジン・ツール・開発チームの継続利用であり、属人的なボトルネック（ディレクター単独の数値入力）を組織的な調整パイプラインへ移行することである。

## AGENT
スクラップ＆ビルドを美徳とせず、安定した基盤の上で全リソースをコンテンツの網羅とブラッシュアップに集中させる判断が、爆発的なスケールを生む。

## Agent questions
- 前作の資産やツールチェインを最大限に再利用できているか？
- コンテンツ量増加に対して、調整作業がスケールアウト可能な組織設計になっているか？

## Suggested actions
- 前作データスキーマからの移行スクリプトおよびパラメータ管理DBを構築する。
- テストプレイ結果をフィードバックし、プランナー複数名で並行調整できるワークフローを策定する。

## Review criteria
- 開発基盤の引き継ぎにより、新規アセット制作・調整にリソースの8割以上を投下できる状態になっていること。
- ディレクターが全体監修に専念できる権限委譲が完了していること。

## Anti-patterns
- 続編ごとにエンジンや開発会社を刷新し、過去作の蓄積したノウハウやアセットをすべて捨てること。
- 数百体規模のキャラクター数値を1人のリードが手作業で入力し続け、開発が停滞すること。
