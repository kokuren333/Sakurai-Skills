# 選択・決定操作の高速化とショートカット設計

## Summary
多数の選択肢や頻繁に行うメニュー遷移は、入力デバイスの特性を最大限に活かし最小の手数と時間で選択できるようにする。

## GENERALIZED
多数の選択肢や頻繁に行うメニュー遷移は、入力デバイスの特性を最大限に活かし最小の手数と時間で選択できるようにする。

## AGENT
Apply as a contextual review heuristic, not an absolute rule.

## Why it matters
ゲーム内のあらゆる場面で「選ぶ」行為が発生するため、選択レスポンスの鈍さは累積して深刻なプレイ体験の悪化（テンポの阻害）を招く。

## Use with context
- Domains: UI/UX, Input Management, Menu Design
- Phases: Concept, System Design, UI Implementation
- Trigger: リストUI、インベントリ、設定メニューの実装・レビュー時

## Agent questions
- 項目数に対してナビゲーション速度が追いついているか？
- ページジャンプやカテゴリフィルタが機能しているか？

## Suggested actions
- リスト要素数が8個を超える場合、ページ送り（L/Rトリガー等）のバインディングを追加する。
- アナログ入力値に対してデッドゾーンと段階的加速度テーブルを定義する。

## Review criteria
- 末尾の項目まで最大2秒以内にアクセス可能であること。
- スクロール移動中の現在位置が視覚的に即座に把握できること。

## Anti-patterns
- 数十件あるリストを十字キーの上下連打/長押しリピートだけで送らせる設計。
- ショートカットを詰め込みすぎて、画面上に操作説明が溢れ初心者が混乱する設計（一般性の喪失）。

## Tradeoffs and exceptions
- Tradeoff: 高速ショートカットを増やしすぎると、熟練者には快適だがUIが複雑化し初見プレイヤーの認知負荷が上がる。
- Exception: 選択肢が2〜3個しかないダイアログや、慎重な確認を要するセーフティ画面（データ削除確認など）。
