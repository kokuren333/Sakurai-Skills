# インプットを太く、アウトプットも太く（クリエイターの代謝向上）

## Summary
偏食せず多種多様な最新・過去の作品をエンディングまで浴びるようにインプットし、日常的に発信・出力せよ。

## SOURCE
ゲームや映像作品をとにかく多くプレイ・鑑賞する。1本を長く遊ぶより多くのタイトルに触れ、規模感を把握するためエンディングまで目指す。同時にコラムやTwitter、日報など日常的にアウトプットする。

## GENERALIZED
クリエイティブな出力の品質と速度は、入力データの多様性・解像度と、日常的な出力チャネルの流動性（代謝）の積で決定される。

## AGENT
エージェントが既存のライブラリやコードベースを調査する際、特定の狭い実装例だけでなく、業界標準や多様なパラダイムを広く参照した上で設計・出力するための指針。

## Why it matters
インプットが細いと時代遅れの仕様や車輪の再発明に陥り、アウトプットが細いと思考が結晶化せずスキルが停滞するため。

## Use with context
- Domains: research, skill_development, team_culture
- Phases: pre_production, continuous_learning
- Trigger: 技術調査、市場調査、またはコードベースの参照パターン探索時

## Agent questions
- 自分の慣れ親しんだ狭い技術スタックやジャンルだけで解決策を考えていないか？
- 調査した内容をチームやコードに還元（アウトプット）するプロセスが組み込まれているか？

## Suggested actions
- 類似機能を持つ他社タイトルやオープンソース実装を最低5例以上調査し、比較表を作成する
- 得られた知見を社内Wiki、日報、またはPRのコミットログに要約して即座にアウトプットする

## Review criteria
- 最新の業界動向やゲーム規模感（ボリューム、演出水準）が反映された提案であること
- 調査だけで終わらず、何らかの具体的成果物（コード、記事、ドキュメント）として出力されていること

## Anti-patterns
- 1つのオンラインゲームだけを何千時間もプレイし、最新の他作品を全く知らないままゲームを設計する
- 大量に勉強・調査しているが、社内ドキュメントもコードも一切書かない

## Tradeoffs and exceptions
- Tradeoff: 広く浅く触れるため、1つの作品を深くやり込む時間は犠牲になる。
- Exception: 特定の競技ゲーム（eスポーツ等）の極限的なバランス調整を行う専門テスター業務。
