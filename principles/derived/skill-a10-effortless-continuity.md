# なぜコラムを続けられたのか（習慣化と脱・気負い）

## Summary
長期的な活動は使命感や過剰な労力を排し、1回あたりのコストを下げて『ラクに習慣化』せよ。

## SOURCE
ファミ通コラムを約19年続けられた理由は、①ディレクターとしてアウトプットが苦にならない、②毎回1時間程度で手をかけない、③業界のためといった使命感を持たず気負わない、の3点。

## GENERALIZED
持続可能性（サステナビリティ）を確保するため、単発のクオリティに過剰なエネルギーを注ぐのではなく、運用プロセスの軽量化と習慣化を優先する。

## AGENT
定期的なリリース、CI/CD、デイリースクラム、技術ブログ更新などの運用において、形骸化や燃え尽き症候群を防ぐための運用設計ルール。

## Why it matters
過度な使命感や高すぎる基準は継続の最大の敵であり、途中で挫折して止まってしまっては長期的な価値が生まれないため。

## Use with context
- Domains: process_design, workflow, documentation
- Phases: maintenance, operation, long_term_development
- Trigger: 反復的なタスク、定期メンテナンス、長期間にわたるプロジェクト運用を設計するとき

## Agent questions
- この作業フローは、毎日/毎週無理なく続けられるほど軽量化されているか？
- 過剰な使命感や完璧主義が、継続のハードルを上げていないか？

## Suggested actions
- 反復タスクの1回あたりの所要時間を計測し、目標時間（例：1時間以内）に収まるよう工程を自動化・削剥する
- 「毎回完璧なものを作る」基準を「8割の完成度で定時に出す」基準に緩和するルールを提案する

## Review criteria
- タスクの継続率・締め切り遵守率が100%近く維持されていること
- プロセスの実行に過度な精神的ストレスや残業が伴っていないこと

## Anti-patterns
- 「ゲーム業界を背負って立つ！」と気負いすぎて、1回の記事やPR作成に数日かけてしまい続かなくなる
- 毎回ゼロから完璧なドキュメントを作ろうとして更新が途絶える

## Tradeoffs and exceptions
- Tradeoff: 単発の爆発的なクオリティは抑えられるが、累積のアウトプット量と信頼性が圧倒的になる。
- Exception: 年に一度のマスターアップ直前の総力戦や、企業の存亡を賭けた単発コンペ。
