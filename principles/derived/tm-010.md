# ディレクターの本質は『切る仕事』：無駄の早期切除と軌道修正

## Summary
ディレクターは機能を作るだけでなく、納期・工数・ハード限界を見越して重すぎる荷物を迅速に切り捨てる決断を下す。

## SOURCE
ディレクションとは『方向を定める』こと。ゲーム開発は予定通りにいかないことが山ほどある（マシンスペック限界、納期の遅延、工数の膨張）。その際、船が沈まないように被害を見越して、重すぎる荷物や燃えそうな荷物を捨てる（機能をオミットする、仕様を縮小する）のがディレクターの極めて重要な仕事である。もっとも困るのは、引き延ばした末に土壇場で『できませんでした』となること。

## GENERALIZED
スコープマネジメントにおける『デ・スコープ（Scope Trimming）』の決断力。プロジェクトの破綻を防ぐ唯一の手段は、早期に不可能な要素を特定し、コアバリューに影響を与えない周辺仕様を意図的に切り捨てることである。

## AGENT
リファクタリングや最適化において、ボトルネックとなっている重厚な機能を削ぎ落とし、よりシンプルで堅牢な代替実装へとフォールバックさせる意思決定ロジックに適用可能。

## Why it matters
切る判断が遅れると、無駄な実装に膨大な人月が費やされ、最終的に全体が未完成のまま沈没する。早期に切ることで、残された重要機能のブラッシュアップにリソースを集中できる。

## Use with context
- Domains: Scope Management, Architecture, Project Crisis
- Phases: Production, Alpha, Beta
- Trigger: マイルストーン遅延リスク検知時、またはパフォーマンス予算（FPS/メモリ）超過時

## Agent questions
- 現在遅延または負荷の原因となっているモジュールは、コアゲームループに不可欠か？
- その機能を全削除、または低コストな静的/簡易実装へ差し替えた場合のインパクトは？

## Suggested actions
- 予算超過時に切り捨て可能な機能候補（Cut Candidates）のリストを即座に作成する。
- カットした機能の依存関係をクリーンにパージし、残存モジュールだけでビルドが通るようリファクタリングを実行する。

## Review criteria
- スコープ削減の判断がクリティカルパスの直前ではなく、早期（リスク検知直後）に行われていること。

## Anti-patterns
- マスターアップ直前まで仕様削減の決断を引き延ばし、最終的にバグだらけの状態でリリースする。
- スタッフの『頑張ればできるかも』という根拠のない希望的観測を信じて放置する。
