# ターゲット層（子ども等）による先入観ゼロのモニター観察

## Summary
ゲームに擦れていないピュアなプレイヤー（子ども等）にテストプレイさせ、意見を聞くのではなくその生の反応と空気感を観察する。

## SOURCE
昔やっていて非常に効果が高かったのが『小学生モニター』。スタッフの子どもや親戚を呼び、お菓子を用意して遊び場のような雰囲気でプレイしてもらう。大人のゲーマーと違ってピュアな反応（どこで詰まるか、どこで飽きるか、何に興奮するか）がダイレクトに出る。言葉で感想を聞くのではなく、プレイ中の様子を実地で観察することが極めて有効。

## GENERALIZED
エキスパート・バイアス（開発者の慣れや業界知識）を完全に排除したユーザビリティテストの実施。ユーザーインタビューの発話データ（建前）ではなく、身体反応・視線・プレイの中断・歓声といった無意識の行動ログ（ファクト）を主たる評価指標とする。

## AGENT
ユーザー行動ログ（テレメトリデータ）のヒートマップ解析や、チュートリアル離脱地点のファネル分析として自動化・システム化できる。

## Why it matters
開発者は操作やルールを知り尽くしているため、初見プレイヤーがつまずくポイント（不親切なUI、分かりにくい導入）を認識できない。子どもの率直なリアクションはゲームの根源的な快感とストレスを露わにする。

## Use with context
- Domains: User Testing, Usability, FTUE (First Time User Experience)
- Phases: Alpha, Beta
- Trigger: チュートリアル実装完了時、または新規UI/UXフロー検証時

## Agent questions
- 前提知識ゼロのユーザーが、画面の指示なしに直感的に次の行動を取れるか？
- 入力待ちで停止している時間（Idle Time）が異常に長い画面はないか？

## Suggested actions
- ランダム入力または初見エミュレートエージェントを走らせ、ナビゲーション不能になるデッドロック地点を検出する。
- プレイヤーの初期セッションにおける離脱ポイント（入力失敗頻発箇所）をログから特定しアラートを出す。

## Review criteria
- 操作説明テキストを読まなくても直感的にゲームプレイが開始できること。

## Anti-patterns
- テストプレイ中に開発者が横から『そこは右ボタンを押すんだよ』と操作を教えてしまう。
- 熟練ゲーマーの意見だけを取り入れて、間口を狭める難度調整やUIにしてしまう。
