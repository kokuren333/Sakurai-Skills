# 体験版（デモ版）の二面性評価とハイリスク管理

## Summary
体験版は最高の認知・試遊ツールだが、開発リソース圧迫、データ解析（リーク）リスク、未完成ゆえの悪評リスクを伴うため、極めて慎重に設計・運用せよ。

## SOURCE
体験版の有効性は高い（知られないより知られたほうが良い）。 しかし制作には莫大な労力がかかる。単にゲーム途中を切り出せば済むわけではない。下手をすると小型タイトル1本分に匹敵する。 リスク1：情報漏洩（ROM内の未公開データ・ネタバレがデータマイニングされる）。 リスク2：二重管理（製品版と体験版の2バージョン管理になり、更新・調整・デバッグの負担が倍増）。 リスク3：バランス未調整による悪評（中途半端なものを出して「つまらない」と見切られる）。 発売後に体験版を出す手法もあるが、効果は限定的。

## GENERALIZED
体験版を出すなら「本編と同等以上の完成度とデバッグ精度」が求められる。 中途半端なデモを出すくらいなら、出さないほうが作品全体の評価を守れる場合がある。

## AGENT
Steam Next Fest等で体験版の重要性は上がっているが、桜井氏の指摘する「データマイニング」「ビルド分岐管理」「未調整デモによるウィッシュリスト削除」のリスクは現代でも完全に当てはまる。

## Why it matters
不完全な体験版は購入意欲を削ぎ、ネット上に悪評を定着させ、本編発売前の致命傷になり得る。

## Use with context
- Domains: Build Engineering, Security, QA, Public Relations
- Phases: Production, Pre-launch
- Trigger: 体験版ビルド作成、Steam Next Fest参加計画時

## Agent questions
- 体験版ROMに本編後半のデータが残存していないか？
- 体験版単体で独立したゲームとしての完結した手応えを提供できているか？

## Suggested actions
- ビルド成果物に対する静的解析スクリプトを実行し、体験版範囲外の文字列・アセット・IDの漏洩を検知・遮断する。

## Review criteria
- 体験版に含まれる全データが公開可能範囲内であること。デバッグレベルが製品版同等であること。

## Anti-patterns
- 本編のビルドからステージフラグだけを制限して体験版として配布する（アセット解析でネタバレ流出）。
- 「まだ開発中だから」と言い訳して、操作感やバランスが悪いまま体験版を公開する。
