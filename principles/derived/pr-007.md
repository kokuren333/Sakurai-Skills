# 公開実機デモ（眼前プレイ）による思考整理と説得力最大化

## Summary
他人の目の前で実際にゲームをプレイして見せることは最高のプレゼンであり、他者への披露を想定した設計は思考整理に直結する。

## SOURCE
桜井氏は「人の目の前でゲームをする」機会が非常に多い（『〜のつかいかた』、日本ゲーム大賞のゲームデザイナーズ大賞、GCCX等）。 公開プレイの注意点： 1. 必殺ワザや最後の切りふだを必ず全て見せる。 2. 圧勝しすぎない（接戦の緊張感を見せる）。 3. 通常ワザも多めに見せ、撮れ高を意識する。 ゲーム内容への深い理解がなければ実演プレイはできない。 「百聞は一見にしかず」。目の前でやって見せるのが最も効果が高い。 「人に教えることで自らも学ぶ（教師が教えられる）」のと同様、人に披露することを想定すると自分の企画・思考が整理される。

## GENERALIZED
「他人にリアルタイムで遊んで見せられるか？」をゲームの操作性・テンポ・可読性のストレステストとする。 実演を想定すると、無駄な待ち時間、複雑すぎる操作、画面の分かりにくさが浮き彫りになる。

## AGENT
開発中のビルドをピッチする際、スライド資料を作る前に「コントローラーを握って3分で魅力を実演できるか」を自問することが最良のプロトタイプ評価となる。

## Why it matters
実演できないゲームは、ユーザーにとっても操作困難で魅力が伝わらない欠陥を抱えている可能性が高い。

## Use with context
- Domains: Game Design, Pitching, UX, Community Management
- Phases: Prototyping, Production, Marketing / PR
- Trigger: プロトタイプ検証、パブリッシャー向けピッチ準備、配信イベント企画時

## Agent questions
- 初見の観客が見て理解できる画面構成とテンポになっているか？
- 全主要アクションがスムーズに披露できる導線になっているか？

## Suggested actions
- 主要メカニクスを網羅する「3分間実演スクリプト」をゲーム内シーケンスとして定義し、テストプレイを行う。

## Review criteria
- 実演時に画面内で何が起きているか、観客が一目で理解できること。

## Anti-patterns
- スライドや企画書の説明ばかりで、動くものを見せない。
- 開発者しかクリアできない複雑な操作や、長時間の仕込みが必要なデモ。
