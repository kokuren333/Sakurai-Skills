# 開発と広報の掛け算原則（両輪駆動）

## Summary
ゲームの成果は「開発力 × 広報力」の掛け算であり、開発者自身も認知獲得へ能動的に関与しなければならない。

## SOURCE
ゲームが面白く高品質であることは大前提だが、知られなければ存在しないのと同じである。 年間1万本以上（Steam単体でも2021年時点で1万本超）のゲームが出る時代において、知ってもらう努力は同等に必須。 桜井氏自身はプロデューサーではなくディレクターだが、参戦ムービーの絵コンテから公式Twitter・ウェブサイトの文面チェックまで山ほど広報に関与している。

## GENERALIZED
開発と広報・パブリッシングは別個のフェーズではなく、開発初期から連動して走るべき両輪である。 クリエイターが「良いものを作れば自然と売れる」と広報を外部任せにすることは、プロジェクト失敗の直接要因となる。

## AGENT
AIエージェントがゲーム制作を行う際、ゲーム本体のコードやアセットだけでなく、 「外部へ伝えるためのキービジュアル、テキスト、切り抜き映えする見せ場」を設計初期から組み込む必要がある。

## Why it matters
数多のゲームが埋もれる市場環境下で、認知ゼロは売上ゼロを意味する。開発者が広報に関与しないと、ゲームの真の魅力がズレて伝達されるリスクが生じる。

## Use with context
- Domains: Project Management, Marketing, Game Design
- Phases: Pre-production, Production, Release / Operations
- Trigger: プロジェクト立ち上げ時、マイルストーン策定時、告知計画策定時

## Agent questions
- この機能/演出は、外部へのプロモーション素材としてそのまま切り出せるか？
- 開発チームが監修可能な広報パイプラインが敷かれているか？

## Suggested actions
- 開発ロードマップと並行して「アピールポイント（Feature Callouts）」の抽出タスクを自動生成する。
- ゲーム内のキーフレームや名場面を自動キャプチャし、広報用ドラフトとしてプールする。

## Review criteria
- 広報マテリアル（画像・テキスト）に開発側の意図・ゲームのコア体験が正確に反映されているか。

## Anti-patterns
- 「広報はパブリッシャーやマーケティングチームの仕事」として開発側がノータッチを貫く。
- 製品完成後に初めて広報計画を立て始める。
