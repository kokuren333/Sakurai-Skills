# プレイ状況と視認性に連動する動的HUD設計

## Summary
画面上のHUDは単に固定配置するのではなく、キャラクターへの追従、被弾時の半透明化、距離に応じたフェードなど、戦闘の邪魔にならないよう動的に制御する。

## GENERALIZED
画面上のHUDは単に固定配置するのではなく、キャラクターへの追従、被弾時の半透明化、距離に応じたフェードなど、戦闘の邪魔にならないよう動的に制御する。

## AGENT
Apply as a contextual review heuristic, not an absolute rule.

## Why it matters
HUDがキャラクターや敵の動作を遮蔽すると理不尽な被弾を生み、逆に情報が少なすぎると状況判断ができず戦略性が崩壊するため。

- Domains: HUD/In-game UI, Visual Effects, Camera Integration
- Phases: Combat Implementation, In-game UI Polish
- Trigger: インゲーム戦闘UI、HUDレイアウト、ネームプレート実装時

## Agent questions
- キャラの重なりに対する透過判定が実装されているか？
- 視覚的ノイズを低減するコンテキストフェードが存在するか？

## Suggested actions
- ワールド空間UI（World Space Canvas/Widget）にカメラ距離およびオクルージョンに応じたアルファフェード処理を組み込む。
- ピンチ状態を画面端のビネット（赤発光など）やゲージのマテリアルアニメーションとして駆動するイベントリスナーを接続する。

## Review criteria
- 激しい戦闘中であっても自機およびターゲットの挙動がHUDによって完全遮蔽されないこと。
- プレイヤーの注視点移動を最小限に抑える情報配置になっていること。

## Anti-patterns
- 不透明なUIウィンドウや巨大なゲージが画面中央付近に常駐し、敵の予備動作を隠してしまう設計。
- どんなに状況が変化しても一切アルファ値やサイズが変わらない硬直したHUD配置。

## Tradeoffs and exceptions
- Tradeoff: 動的HUDは没入感と視認性を高めるが、アニメーションや半透明化の頻度が高すぎるとHUD自体の点滅がノイズになる。
- Exception: 静止画的な精密射撃を要求するスナイパーライフルスコープ画面や、シミュレーションゲームの固定情報パネル。
