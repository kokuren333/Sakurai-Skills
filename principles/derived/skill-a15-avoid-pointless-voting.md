# 無意味な多数決（合議の凡庸化と責任者の独断）

## Summary
ゲームの内容や仕様の決定に安易な多数決を用いるな。全体像を把握する責任者が独断で決定せよ。

## SOURCE
企画や仕様の決定で多数決は避けるべき。多数決で選ばれるのは『無難＝平凡』。企画段階で否定された仕様が作ったら面白かった例はザラにある。責任者が正しい情報をもとに独断で決めるべき。

## GENERALIZED
クリエイティブな意思決定において民主主義的合議を排し、全体最適とビジョンを一貫して保持する単一の責任者（Single Threaded Owner）による独断を優先する。

## AGENT
チーム内の対立時、エージェントが「多数決で決めましょう」と提案するのを禁止し、要件の全体像とトレードオフを整理してリード/ディレクターに決断を仰ぐプロセス。

## Why it matters
多数決は最も尖った革新的アイデアを削ぎ落とし、誰も反対しないが無個性で退屈な『平均的仕様』に収束してしまうため。

## Use with context
- Domains: decision_making, game_direction, team_management
- Phases: specification, feature_selection, review
- Trigger: チーム内で設計方針や仕様が対立し、膠着状態に陥ったとき

## Agent questions
- 対立を収めるために、安易な投票や足して2で割る妥協案に逃げていないか？
- 全体像と長期ビジョンを理解している責任者が、根拠を持って独断で下した結論か？

## Suggested actions
- 対立する各案のメリット・デメリットと、プロジェクトのコアゴールに対する適合度を整理した決裁資料を作成する
- 多数派の意見であっても『無難で平凡』な案に対しては、革新性が失われるリスクを指摘する

## Review criteria
- 意思決定の根拠が『多数の賛同』ではなく『製品コンセプトへの合致』であること
- 最終決定者の名前と責任の所在が明確に記録されていること

## Anti-patterns
- チーム内の多数決で新機能の採用を決め、結果として誰も熱狂しない無難なゲームになる
- 『MGS3』のキュアーシステムのように、当初スタッフの4人しか賛成しなかった革新的な仕様を多数決でボツにする

## Tradeoffs and exceptions
- Tradeoff: 独断で決める責任者に極めて高度なバランス感覚と責任が要求され、ワンマン化のリスクを孕む。
- Exception: 飲み会の場所決め、余興のメイド服のカラーバリエーション選定など、本質的ゲーム性に影響しない瑣末な決定。
