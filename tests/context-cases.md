# Context sensitivity examples

These are review fixtures, not claims about actual games. A reviewer should change recommendations when audience, phase, and constraints change.

## A: Beginner action game, first playable
- Context: unfamiliar controls, broad audience, low-cost prototype.
- Relevant focus: onboarding clarity, readable response, low-friction retry.
- Useful question: can a new player infer the next action without a long explanation?
- Avoid assuming: every challenge should be easy; validate intended challenge separately.

## B: High-difficulty expert game, balance pass
- Context: expert audience, mastery is central, late tuning phase.
- Relevant focus: legible failure, meaningful risk/reward, precise control response.
- Useful question: does failure communicate a learnable cause and preserve agency?
- Avoid assuming: remove demanding execution or every retry cost.

## C: Experimental indie game, concept prototype
- Context: unfamiliar interaction, small team, concept still uncertain.
- Relevant focus: prototype the central hypothesis, preserve room for discovery, keep scope small.
- Useful question: what is the cheapest test that distinguishes a compelling novelty from confusion?
- Avoid assuming: immediately add conventional onboarding or polish before testing the interaction.

## Expected distinction
All cases consider player understanding and evidence. The first emphasizes first-use support, the second preserves intentional mastery while improving legibility, and the third prioritizes learning about novelty before standardization.
