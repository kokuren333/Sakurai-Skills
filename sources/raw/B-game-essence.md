桜井政博のゲーム開発設計原則（カテゴリーB：ゲーム性編）

本書は、ゲームデザイナー・桜井政博氏が解説したゲーム制作における「ゲーム性」の本質とバランス調整手法を、ソフトウェアエンジニアおよびAIコーディングエージェントが実装・評価可能な形に再構成したスキルガイドラインです。

原則1：リスクとリターンの対構造設計（GAMEPLAY_CORE_001）

  - ルールの要約: ゲーム性とは「リスクを冒してリターンを得るかけひき」であり、攻略とは「リスクを抑えてリターンを得る工夫」である。
  - 本質の解説:
      - 明示的説明:
        『スペースインベーダー』において、砲台が敵の直下に潜り込むと被弾リスクが跳ね上がるが、弾の往復時間が短縮されて敵を素早く撃破できる。この「危険と利益の表裏一体」こそがゲーム性の正体である。
      - 合理的一般化:
        プレイヤーの行動選択肢において、「ノーリスク・ハイリターン（安全かつ圧倒的に有利）」な状態が存在すると駆け引きが崩壊するため、リターンの大きさに応じてリスク（被弾率、硬直時間、リソース消費）を比例配置しなければならない。
  - AI Agent 実行指針:
      - agent_trigger: プレイヤーの技、武器、特殊能力のパラメータを設定するとき。
      - agent_actions: 高威力技の発生フレームを遅くするか、後隙（硬直）を長くする。遠距離武器の弾数を制限し、リロード時に無防備にする。

原則2：ストレス付与と急激な解消のサイクル（GAMEPLAY_CORE_002）

  - ルールの要約: 障害によってプレイヤーにストレスを「ギュッ」とかけ、それを「パッ」と解放・解消させることで快感を生み出す。
  - 本質の解説:
      - 明示的説明:
        客観的に見ればストレスは無いほうが快適に思えるが、ストレスがない平坦な道には達成感も快感も存在しない。ギュッと負荷をかけ、突破時にパッと解消する落差こそがゲームの面白さの核となる。安易に雑草を抜くようにストレス要素を取り除いてはならない。
      - 合理的一般化: 難所・リソース制限・障害で緊張を高め、撃破・クリアの瞬間にエフェクトや報酬で緊張を一気に弛緩（リリース）させる。
  - AI Agent 実行指針:
      - agent_trigger: ステージの難易度や障害配置を見直すとき。
      - agent_actions:
        障害（敵・罠）を突破した直後に明確な「安全地帯」と「報酬演出」をセットで配置し、緊張と緩和のコントラストを最大化する。

原則7：リトライ時間の極小化（GAMEPLAY_UX_009）

  - ルールの要約: ミスから再開までの時間はプレイヤーの熱量が急速に冷める魔の時間であり、演出を絞りロードを短縮して極力迅速に操作権を返す。
  - 本質の解説:
      - 明示的説明:
        プレイヤーに何の感情も与えない暗転や待ち時間が長引くほど、プレイヤーは急激に冷めてゲームをやめてしまう。演出は短く派手にストーンと入れ、冷める前に操作のバトンをプレイヤーに戻す。
      - 合理的一般化: 失敗時の心理的摩擦（フリクション）を極限まで低減することで、試行錯誤のループ（やり込み）を維持させるUXの鉄則。
  - AI Agent 実行指針:
      - agent_trigger: プレイヤーの死亡処理・リスポーン遷移の実装時。
      - agent_actions:
        死亡判定からリスポーン完了・入力受付までの遅延を計測し、演出アニメーションのスキップ処理およびアセットの非同期プリロードを実装する。

原則8：難易度曲線の「山あり谷あり」波状設計（GAMEPLAY_BALANCE_011）

  - ルールの要約: プレイヤーの成長と敵の強さを比例直線で平行進化させてはならず、乗り越えるべき壁（ボス）と楽ができる平地（休息・無双）の凹凸を作る。
  - 本質の解説:
      - 明示的説明:
        自分の強さと敵の強さが常に正比例していると、延々と平坦な坂を登り続けるような作業になる。敵が強くなる山（ボス）があり、それを越えたら強くなった実力を試せる平地（楽勝な雑魚戦・稼ぎ場）があるという凹凸が必要である。
      - 合理的一般化: 全自動の敵レベルスケーリング（プレイヤーに合わせた敵の強化）を無差別に適用すると、キャラクターを強化する動機が消失する。
  - AI Agent 実行指針:
      - agent_trigger: エネミーのステータス計算式、エリア難易度テーブルの作成時。
      - agent_actions:
        プレイヤーの現在レベルに完全に同期する敵パラメータ計算を廃止し、エリアごとに固定のレベル格差を設定して、成長実感を得られるボーナス期間を設ける。

原則9：長所を伸ばし短所も伸ばす尖鋭化調整（GAMEPLAY_BALANCE_012）

  - ルールの要約: 突出した強さを削って弱点を埋める平均化は没個性の滅びの道であり、個性を残すために長所を伸ばしつつ短所も伸ばして尖らせる。
  - 本質の解説:
      - 明示的説明:
        スマブラのファイター調整において、強すぎる部分を削って谷を埋めると、全員が同じような性能のキャラクターになり、ゲームが没個性化して死ぬ。攻撃力や特長という山は残し、後隙の長さやリーチの短さといった短所を伸ばすことで、凹凸のある尖ったバランスを維持する。
      - 合理的一般化: パラメータのナーフ（下方修正）を行う際は、アイデンティティとなっている得意領域には手を触れず、苦手領域のペナルティを重くする。
  - AI Agent 実行指針:
      - agent_trigger: キャラクターや武器の弱体化・調整パッチ作成時。
      - agent_actions: 技のヒット判定やダメージ値を下げる代わりに、発動後の硬直フレームや空振り時の被ダメージ倍率を増加させる。

原則10：開発者バイアスの排除とハンデ検証（GAMEPLAY_TESTING_014）

  - ルールの要約: 開発スタッフは一般プレイヤーより何十倍もゲームに慣れていることを自覚し、片手プレイ等の物理的ハンデを課して難易度を検証する。
  - 本質の解説:
      - 明示的説明:
        開発者は毎日何時間もそのゲームを触っているため、無意識にプレイスキルが超人的になっている。開発者が「ちょうどいい、少し簡単かな？」と思う難易度は、初見のユーザーにとっては難しすぎてクリア不能である。桜井氏はコントローラーを机に置いて片手でプレイするなどのハンデを課して適正難易度を測る。
      - 合理的一般化: 開発環境で得られる「体感難易度」は常に下方修正（1〜2ランク下げる）して本番環境に適用しなければならない。
  - AI Agent 実行指針:
      - agent_trigger: ボス戦やアクションステージのパラメータ最終調整時。
      - agent_actions:
        自動テストを行うエージェントに対し、ランダムな入力遅延（フレームドロップ擬似再現）や一定確率のミス入力を強制的に注入し、それでも勝率が50〜70%を維持できるかを検証する。

3. Knowledge Engineerによる考察とエージェントへの統合指針

A. 桜井氏の明示的説明の核

桜井氏の設計哲学の根底にあるのは**「二項対立の調停」**です。「リスク」と「リターン」、「ストレス」と「緩和」、「ゲーム性（駆け引き）」と「一般性（アクセシビリティ）」、「長所」と「短所」。これらをどちらか一方に倒すのではなく、両端を引っ張ってテンション（張力）を生み出すことを面白さの源泉としています。

B. AIエージェントへの適用モデル

AIがゲームを設計・コーディングする際、数値を平均化（均等分散）しようとするアルゴリズム的バイアスがかかりがちです（例:
全武器のDPSを完全に一致させるなど）。しかし、本リポジトリの原則（特にB28、B13、B01）は、**「意図的に凹凸を作ること」「尖らせて弱点を作ること」**を要求します。

エージェントがゲームバランスをコード化する際は、以下の評価関数を適用してください：

1.  トレードオフが存在するか？（最強の選択肢に、致命的な弱点が内包されているか）
2.  プレイヤーに能動的な選択肢があるか？（難易度やリスクを自己決定できているか）
3.  リトライのフリクションがゼロに近いか？（ロードや演出で熱を冷ましてしまっていないか）
