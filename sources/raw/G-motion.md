SKILL-MOT-001: ダメージ初動の極端化とヒットストップ連携

  - ワン文ルール: ダメージを受けた最初の1フレーム目は、ヒットストップ中に最も視認されるため、待機姿勢とは完全に異なる極端で痛烈なポーズを即座に取らせよ。
  - 解説:
      - A. 明示的内容:
        『スマブラ』では被弾した瞬間（1F目）に痛そうなポーズに即座に置き換わり、そこにヒットストップがかかる。待機ポーズに近いと被弾したことが伝わらないため、遠くから見ても一目でわかる極端なポーズをとらせる。
      - B. 合理的設計原則:
        ヒット感の正体は「ヒットストップ中の静止画の強度」にある。被弾1フレーム目は補間を排除し、最大変形ポーズを即座に提示することで、打撃の重さと手応えを伝える。
      - C. 補足・解釈: 物理ブレンドを被弾の初動に適用すると、ダメージの衝撃が吸収されたように見え、アクションの手応えが著しく低下する。
  - なぜ重要か: 遠く離れた引き視点でも「誰が、どれほどのダメージを受けたか」を瞬時に判別させ、ゲームの納得感と快感を最大化するため。
  - AIエージェント向け指示:
      - agent_trigger: 被弾ステートマシンの遷移、ダメージモーションの1F目の調整時
      - agent_questions: 待機ポーズと被弾ポーズのシルエットが即座に区別できるか？ ヒットストップ中に最も痛そうな形になっているか？
      - agent_actions: 被弾遷移ブレンド時間を0Fに設定。首・手足の反りを誇張したキーポーズを配置。
      - agent_review_criteria: 静止画キャプチャ1枚で「強烈なダメージを受けた」ことが明確に視認できること。

SKILL-MOT-002: 被弾時TOPノード保持とコンボ成立性の担保

  - ワン文ルール:
    ダメージモーションで姿勢を大きく崩す際も、モデル中心（TOPノード）と食らい判定の位置を安易に後退させず、後続の攻撃が抜けないよう設計せよ。
  - 解説:
      - A. 明示的内容:
        マリオの弱攻撃コンボ中、相手（マルス等）のやられモーションで体勢が崩れ、TOPノードが後ろに逃げると後続のパンチが空振りしてしまう。製品版ではこれを改善した。
      - B. 合理的設計原則:
        演出上のメッシュ変形と、ゲームシステム上の当たり判定（Hurtbox）および中心座標（Root）を幾何学的に切り離し、連続技の確実性を保証する。
      - C. 補足・解釈: 痛烈さを表現するために上体を反らせる場合でも、前足や腰のコリジョンを前方に残すアンカー処理が必要となる。
  - なぜ重要か: 見た目の演出を優先した結果、入るべきコンボが理不尽に抜け、プレイヤーが操作上のバグや不公平感を感じるのを防ぐため。
  - AIエージェント向け指示:
      - agent_trigger: 弱攻撃連撃や近接コンボの仕様策定、被弾コリジョン調整時
      - agent_questions: 被弾アニメーションの再生によって、相手の食らい判定が攻撃側の攻撃判定外へ逃げていないか？
      - agent_actions: 被弾側のHurtboxの前方ボリュームを維持。TOPノードの後退を制限。
      - agent_review_criteria: キャラクターの体格差に関わらず、設計通りの連続攻撃が全段安定してヒットすること。

SKILL-MOT-004: モーション補間の間引きと初動キレの創出

  - ワン文ルール: 3Dツールの自動補間に任せず、かまえから攻撃ポーズへの遷移（中割）を極限まで間引き、初動のタメと打撃瞬間のポーズに時間を配分せよ。
  - 解説:
      - A.
        明示的内容: 2Dドット絵の技を3D化する際、均等に中割りを自動補間すると「ぬるい動き」になってしまう。テリーのキックやリュウのアッパーのように、中割りをほぼ無くし（1F等）、かまえと攻撃ポーズに時間を割くことでキレが生まれる。
      - B. 合理的設計原則:
        リアルな連続補間は「鈍さ」を生む。打撃のスピード感は「タメ（予備動作）で粘り、一瞬でインパクトに到達する」非対称な時間配分によって生み出される。
      - C. 補足・解釈: 自動補間が便利になった現代だからこそ、意図的に補間を「殺す」コマ打ちの感覚が格闘・アクションゲームには不可欠である。
  - なぜ重要か: 物理的に滑らかなだけのモーションは操作感が重く感じられ、ヒット時の爽快感とキレ味が完全に失われてしまうため。
  - AIエージェント向け指示:
      - agent_trigger: 攻撃アニメーションのFカーブ編集、2D格闘技技の3D再現時
      - agent_questions: かまえからインパクトまでの間に不要な中割り補間が挟まり、パンチの初動が鈍くなっていないか？
      - agent_actions: 中割フレームを削除し、かまえからインパクトへ1〜2フレームで一気に跳躍させる。タメのポーズを大きく引き絞る。
      - agent_review_criteria: アクション全体の発生フレームが維持されたまま、視覚的なキレと速度感が劇的に向上していること。
  - 出典: File G11 (04:19 - 08:35)

SKILL-MOT-005: フォロースルー軌道の非対称化（行きの軌跡をなぞらない）

  - ワン文ルール: 攻撃後のフォロースルー（戻り動作）は、行きと同じ軌跡を往復させず、別軌道を通すことで硬直時間を有効に使った豊かな余韻を演出せよ。
  - 解説:
      - A. 明示的内容:
        攻撃が終わった後の動作（フォロースルー）は、行きの軌跡をそのまま逆再生して戻してはならない。リュウのアッパーでは、突き上げた腕を外回りに大きく旋回させて戻すことで、隙を使い切る豊かな余韻を演出している。
      - B. 合理的設計原則:
        人体や武器の運動において、エネルギーを逃がす戻り動作は別の弧（アーク）を描く。戻りを別軌道にすることで、アニメーションに深みとダイナミクスを与える。
      - C. 補足・解釈: フォロースルーはプレイヤーが操作できない時間だが、視覚的に最も長く画面に留まる。ここを往復運動にすると一気に手抜き感が出る。
  - なぜ重要か: 攻撃の硬直時間が単なる「操作不能の待ち時間」から「技の威力を感じさせる心地よい余韻」へと昇華されるため。
  - AIエージェント向け指示:
      - agent_trigger: 攻撃モーションのリカバリーフレーム作成、モーションカーブ調整時
      - agent_questions: 振り切った手足や武器が、放った時と全く同じ空間を通って戻っていないか？
      - agent_actions: 戻り軌道に外回りや下回りのカーブを設定し、行きと戻りの軌跡を楕円状に分離する。
      - agent_review_criteria: 軌跡表示（Motion
        Trail）で行きと戻りのカーブが美しく分離し、一連の円環・流線を描いていること。
  - 出典: File G11 (07:39 - 08:35)

SKILL-MOT-006: 引き視点CGにおけるフェイシャルの過剰誇張

  - ワン文ルール: 俯瞰・引き視点のゲーム画面では表情情報が著しく減退するため、目・口・顎の変形を解剖学的限界以上に大げさに動かせ。
  - 解説:
      - A. 明示的内容:
        深作欣二監督の遺作『クロックタワー3』の「CGは情報が減るから大げさに演技する」という教えの通り、CGキャラクターは極端に動かす必要がある。ウルフの被弾顔の顎を外すような開口、白目の露出、前歯の噛み合わせ回避など、限界を超えたレタッチを行う。
      - B. 合理的設計原則:
        遠景カメラによる解像度低下を、変形スケールの誇張によって相殺する。クローズアップでは過剰に見えるレベルの変形が、プレイ画面では「標準」として知覚される。
      - C. 補足・解釈: リアルの模倣ではなく「記号としての伝達力」を優先する。特に目と口の開き方は、影の落ち方まで考慮してオーバーに造形する。
  - なぜ重要か: 引いた画面の中でキャラクターの表情が死に、無機質で生気のないマネキンに見えてしまうのを防ぐため。
  - AIエージェント向け指示:
      - agent_trigger: フェイシャルブレンドシェイプの作成、アクション時の表情付け時
      - agent_questions: ゲームプレイ中の通常カメラ距離で、キャラクターの感情（苦痛、気迫）が判読できるか？
      - agent_actions: 開口幅・目見開きブレンドシェイプの最大値を130%〜150%に拡大。上下前歯が重ならないよう顎を下方にシフト。
      - agent_review_criteria: 実機プレイ距離の引き視点キャプチャで、表情が生き生きと認識できること。
  - 出典: File G12 (08:38 - 10:55)

SKILL-MOT-007: フリップモーション（左右反転時の非対称演出）

  - ワン文ルール: サイドビュー画面でキャラが左右に向きを変える際、単なる軸反転ではなく、常にお腹と顔が手前を向く鏡対象モーションを用意せよ。
  - 解説:
      - A. 明示的内容:
        『スマブラ』では左右に向きを変えた際、マリオのように左右どちらを向いてもお腹が手前を向く技術（フリップモーション）を導入している。普通に反転すると片方が背中を向けてしまい、表情が見えず情報量が低下するため。ただし、剣や盾など左右非対称の装備を持つキャラ（リンク等）は破綻を避けるため適用しない。
      - B. 合理的設計原則:
        サイドビューアクションにおいて、手前側カメラに対するキャラクターの露出情報量を最大化する。単純な180度回転による「背中向け」を排除し、2Dスプライト的な見栄えの良さを3Dで再構築する。
      - C. 補足・解釈:
        カービィのような球体キャラであっても、正中線をわずかに傾けて手前を向かせることで、常に愛らしい表情とアクションをプレイヤーに提示できる。
  - なぜ重要か: キャラクターの顔や衣装の主特徴が背中を向けることで隠れ、画面の華やかさと視認性が半減するのを防ぐため。
  - AIエージェント向け指示:
      - agent_trigger: 2.5Dゲームのキャラクタコントローラ実装、向き反転システムの設計時
      - agent_questions: 左右に向きを変えた際、片方の向きでキャラクターが背中を向けてしまっていないか？
      - agent_actions: 左右対称キャラクターに対してポーズを鏡対象化するフリップロジックを実装。非対称装備キャラは例外フラグで除外。
      - agent_review_criteria: 左右どちらを向いた状態でも、顔とお腹が常に手前カメラ側を向いていること。
  - 出典: File G13 (10:56 - 13:55)

SKILL-MOT-008: キャンセルフレームとモーションブレンドの調停

  - ワン文ルール:
    攻撃後の硬直をキャンセルして次の動作へ移る際は、適切なブレンド時間を設定して硬さを防ぎつつ、補間が長すぎてキレを殺さないバランスを死守せよ。
  - 解説:
      - A. 明示的内容:
        『スマブラDX』まではキャンセルがなく待機ポーズに戻るまで操作不能で重かったが、以降はフォロースルー中にキャンセルフレームを設定し、移動やジャンプへ即座に移行できるようにした。その際のモーションブレンドは、長すぎるとキレが失われ破綻するためパッと行う。
      - B. 合理的設計原則:
        アクションの軽快さは「先行キャンセル」によって生み出される。遷移時のポーズ崩壊を防ぐブレンドは必要だが、ブレンド時間は数フレームの極小に抑え、キビキビ感を最優先する。
      - C. 補足・解釈: 待機ポーズと歩行初動ポーズが合わさる「のりしろ」のブレンド時間をミリ秒単位で詰めることが、手触りの良さに直結する。
  - なぜ重要か: 操作レスポンスの軽快感（入力がすぐ反映される気持ちよさ）と、見た目の破綻防止を両立させるため。
  - AIエージェント向け指示:
      - agent_trigger: コンバットステートマシンの遷移設定、キャンセル可能フレームの策定時
      - agent_questions: 攻撃後の硬直が長すぎて操作が重く感じられないか？ ブレンドが長すぎて次の動作がフニャついていないか？
      - agent_actions: フォロースルーの後半にCancel
        Windowを設定。遷移ブレンド時間を2〜4フレーム（約0.05秒）前後の極小値に設定。
