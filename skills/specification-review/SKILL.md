---
name: specification-review
description: Turn game behavior into clear, implementable, reviewable specifications.
---

# Use when
Writing or reviewing mechanics, UI, parameters, task tickets, acceptance criteria, or cross-discipline handoffs.

# Procedure
1. State intent, player-visible behavior, states, triggers, parameters, ownership, and dependencies.
2. Mark open questions separately from decisions and implementation suggestions.
3. Check edge cases, units, timing, failure behavior, and testable acceptance evidence.
4. Load `specification` and relevant domain candidates from `principles/catalog.json`.
5. Keep documentation proportional to stability and coordination needs.

# Output
Ambiguities, missing behavior, dependencies, proposed wording, acceptance checks, and owner questions.
