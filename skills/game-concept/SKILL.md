---
name: game-concept
description: Define or review intended player, game promise, concept, and core loop.
---

# Use when
Starting a concept, revising direction, evaluating feature fit, or clarifying what makes a game distinct.

# Procedure
1. State intended player, desired experience, fantasy, repeated actions, and constraints.
2. Express the core loop in player verbs and observable outcomes.
3. Identify what makes the concept distinct and which assumptions are unproven.
4. Sort features by contribution to the promise, cost, and uncertainty.
5. Propose a minimal prototype for the riskiest assumption.

# Relevant principles
`preserve-core-concept`, `player-agency-and-tradeoffs`, `prototype-before-polish`, `design-for-context`, `test-with-representative-players`.

# Output
Concept statement, core loop, audience assumptions, risks, scope candidates, prototype question, and evidence that would change direction.

# Guardrails
A concept is a guide, not a reason to dismiss contrary player evidence. Genre conventions are optional unless the project requires them.
